Who this is for

For independent online stores that sell through Shopify or WooCommerce and need a cleaner handoff between the storefront, support desk and bookkeeper. We scope one store platform at a time, not a forced migration.

Problems worth solving

Support cannot see the full order story

A shipping question may refer to an edited order, partial fulfillment or refund request. We can prepare a source-linked support brief and a reply draft instead of making the customer repeat everything.

Gross sales do not explain a payout

Discounts, taxes, shipping, fees and refunds can be spread across different records. A review worksheet can separate those amounts and flag missing evidence before your bookkeeper decides how to record them. Processor payout access is verified separately.

What a custom workflow could look like

  1. Read an authorized order event or approved export and preserve the store order ID as the matching key.
  2. Classify the office task—such as a shipping question or a refund request—and gather only permitted order details.
  3. Prepare a draft response or exception summary. Missing or redacted fields are shown as unavailable, never invented.
  4. Where payout evidence is available, assemble a gross-to-net comparison for the bookkeeper, including refunds and processor fees as separate review items.
  5. A person approves customer communications and every accounting posting. Refunds, fulfillment decisions and inventory purchases remain human-controlled.

Illustrative design only—not a client story, measured result or demonstration of a live integration.

Access and plan limitations

Shopify’s GraphQL Admin API requires a store access token and merchant-approved scopes. Protected customer data access depends on app type and approval; access to identifying fields for admin-created custom apps can vary by plan. Historical order access and payment-provider records need separate checks. WooCommerce provides a REST API with user-linked keys and explicit permissions; current supported WordPress/WooCommerce versions, pretty permalinks, HTTPS and hosting/security compatibility must be confirmed. Extensions may require their own API and subscription; the store API is not universal access to every gateway.

Questions before you start

Does the integration issue refunds automatically?

No. It can prepare an exception brief. Refunds and other money-moving actions stay with an authorized person.

Can every app read customer names and emails?

No. Shopify protected-data rules depend on app type, requested fields and approvals; some admin-created custom app access varies by plan. We confirm the actual fields before quoting.

Does WooCommerce require a special paid API tier?

The core REST API documentation does not specify a separate paid API tier. Your hosting, user permissions, security configuration and paid extensions can still affect access and cost.

Will this handle sales-tax filing?

No. It organizes evidence for your bookkeeper and CPA. Tax treatment and filing remain with qualified people; no autonomous filing or payments are included.
